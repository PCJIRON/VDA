      - `__init__(self, api_client, tool_registry=None, settings=None)` — Store api_client for sub-agent API calls. Use `get_registry()` if tool_registry not provided.
      
      - `async def spawn_and_execute(self, context: SubAgentContext) -> SubAgentResult:` — Main entry point:
        1. Build the sub-agent system prompt using context + scoped tool definitions
        2. Get tool definitions via `self._registry.get_definitions(agent_type=context.agent_type)`
        3. Call LLM with isolated context window (separate `api_client.send_message()` call)
        4. Parse the response for tool calls and final output
        5. Execute any tool calls through the ToolRegistry (only tools in sub-agent's scope)
        6. Return SubAgentResult with structured output

        ```
        Goal: {original_goal}
        Context: {preceding_work}
        Task: {subtask}
        Constraints: {constraints}
        
        Available tools:
        {tool_definitions_json}
        
        Respond with tool calls when needed. Return "TASK_COMPLETE" when finished.
        ```
      
      - `async def _execute_sub_agent_tool(self, tool_name: str, args: dict) -> str:` — Execute a single tool call through the registry. Get tool instance via `self._registry.get_tool(tool_name)`, call `await tool.execute(**args)`. Return result string.
      
      - `def get_available_agent_types(self) -> list[str]:` — Return agent types from AGENT_TYPES config: `list(AGENT_TYPES.keys())` or `["main", "web", "terminal", "file", "voice"]` if config not available.
      
      - Module-level logger: `logger = logging.getLogger(__name__)`

    - Key design decisions per research:
      - Full reasoning sub-agents (separate API call, own context window) — per research §discretion recommendation
      - Single registry with scope filtering — `get_registry().get_definitions(agent_type="web")` returns only web tools
      - Structured SubAgentContext prevents context loss (per §Pitfall 3)
      - Tool calls execute within sub-agent's scope only

    Create `core/agent_manager/session_compactor.py` following research §Session Compactor code example:

    - Module docstring, module-level logger
    - Imports: `logging`, `from typing import Optional`, `from qwen_desktop.core.api_client import APIClient`

    - `COMPACTION_PROMPT` constant (multiline string, exactly per research):
      ```
      Summarize the conversation so far for continuation. Preserve all critical details:
      
      CRITICAL — must preserve exactly:
      - File paths and file contents modified
      - Exact error messages and error codes
      - Decisions made and the reasoning
      - Commands executed and their output
      - Current task state and what remains incomplete
      
      Format:
      ## COMPACTED CONTEXT
      **Task:** {original_task}
      **Files modified:** [paths]
      **Errors:** [exact messages]
      **Decisions:** [key decisions with rationale]
      **Pending:** [what remains to be done]
      **Summary:** {conversation_summary}
      ```

    - `class SessionCompactor:` with:
      - `__init__(self, api_client, threshold: float = 0.8, max_tokens: int = 128000)` — Per research defaults. Also accept `self._compacted = False` flag
      
      - `@staticmethod def estimate_tokens(messages: list[dict]) -> int:` — Rough estimation: `total_chars // 4`. Per research A5 — "accurate enough for compaction threshold."
      
      - `async def needs_compaction(self, messages: list[dict]) -> bool:` — Check if compaction needed based on token threshold:
        1. If `self._compacted` already true → return False (one-time per session, per research)
        2. Calculate `tokens = self.estimate_tokens(messages)`, ratio = tokens / max_tokens
        3. Log: `logger.info(f"[Compact] Token ratio: {ratio:.1%} ({tokens}/{self.max_tokens})")`
        4. Return `ratio >= self.threshold`
      
      - `async def compact(self, messages: list[dict], original_task: str) -> list[dict]:` — Per research code example:
         1. Find oldest user message index
         2. Build portion to compact from oldest user message to second-to-last
         3. Call LLM with COMPACTION_PROMPT for structured summarization
         4. Build compacted message list:
            - First message: `{"role": "system", "content": f"[Previous context compacted: {summary[:2000]}]"}`
            - Keep last user message if it exists
         5. Set `self._compacted = True`
         6. Log: `logger.info(f"[Compact] Done: {len(messages)}→{len(compacted)} messages")`
         7. Return compacted messages
       
       - The caller (AgentWorker in Plan 04) is responsible for writing the compacted context back to SessionService. SessionCompactor only handles the summarization and message list transformation.
      
      - `def reset(self) -> None:` — Reset `self._compacted` flag for new session
      
      - Module-level logger

    - Update `core/agent_manager/__init__.py` to add:
      ```python
      from qwen_desktop.core.agent_manager.sub_agent_delegator import SubAgentDelegator, SubAgentContext, SubAgentResult
      from qwen_desktop.core.agent_manager.session_compactor import SessionCompactor
      ```
      And add to `__all__`.

    - Key design decisions per research:
      - Auto-summarize at threshold (not truncate old or manual-only) — per research §discretion recommendation
      - Structured summarization preserves critical details (not free-form) — per §Pitfall 4
      - One-time per session to avoid re-compaction loops — per research code example
      - Token estimation via char_count // 4 (rough but sufficient) — per research A5

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SubAgentDelegator → LLM API | Sub-agent receives structured context from parent; AI-generated tool calls cross back into execution |
| SessionCompactor → LLM API | Conversation history sent to LLM for summarization — summary re-enters context as system message |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Spoofing | SubAgentContext injection | mitigate | Sub-agent only receives structured context from parent AgentManager, NOT raw user input. Context added via template, not string interpolation from untrusted data. |
| T-02-09 | Information Disclosure | SessionCompactor LLM call | accept | Conversation sent to LLM for summarization. Since the same provider is used for execution, no additional disclosure beyond normal API calls. User configured provider via Settings. |
| T-02-10 | Tampering | SessionCompactor structured fields | mitigate | Structured fields (Files, Errors, Decisions) are LLM-generated — treated as hints, not ground truth. Original tool call records in session JSONL remain unchanged. |
| T-02-11 | Denial of Service | Sub-agent infinite loops | accept | Sub-agents have their own max_iterations limit inherited from parent AgentManager config. Parent monitors sub-agent call count. |
| T-02-SC | Tampering | No packages installed | mitigate | This plan installs NO new packages. All code uses Python stdlib + existing stack. Slopcheck bypass valid. |
</threat_model>
